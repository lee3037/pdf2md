# PDF → FastGPT 知识库 Markdown

在线把 PDF（文本型、扫描型）转换为结构清晰、已按语义分块并插入分隔符的 Markdown，可直接导入 FastGPT 知识库。

## 快速开始

```bash
./run.sh            # 默认端口 8000；首次运行自动创建 .venv 并安装依赖
./run.sh 9000       # 指定端口
```

浏览器打开 `http://<服务器>:8000/`，拖入 PDF 即开始转换。完成后在"分块"视图逐块检查（可直接编辑、合并、删除，点击页码对照原文），左侧调整分块参数会自动重新分块，最后下载 `.md`。

导入 FastGPT：新建/打开知识库 → 文本数据集 → 本地文件导入 `.md` → 处理方式选"直接分块"，分块模式选"自定义分隔符"，填入与本工具一致的分隔符（默认 `===CHUNK===`）。FastGPT 的"最大分块大小"应不小于本工具的"最大字数"，否则块会被二次截断。

## 功能

| 需求 | 实现 |
|---|---|
| 文本型 / 扫描型 PDF | PyMuPDF 版面模型做版面分析；无文字层或文字乱码的页自动用 RapidOCR 识别（可选强制/关闭） |
| 标题层级 | 编号体例（第X章/第X节/一、/（一）/1./1.1/1.1.1/（1）/附录/Chapter…）+ 出现顺序 + 字号推断；PDF 有书签目录时以目录校正 |
| 正文、列表、阅读顺序 | 双栏阅读顺序；按缩进/句末标点拆段；中文折行直接相连、英文断词连字符合并；项目符号与编号列表规范化，按缩进嵌套 |
| 页眉、页脚、页码 | 版面模型识别 + 页面边缘跨页重复文字检测 + 页码格式识别（`- 3 -`、`第3页 共10页`、`3/10`、`Page 3 of 10`…） |
| 跨页 / 跨栏 | 跨页、跨栏、被版面模型切开的段落自动续接；跨页表格自动合并（去重复表头、去"续表"、首列为空的行接回上一行） |
| 表格 | 有框线表格按真实框线取单元格并按字符坐标取文字；合并单元格内容填充到其覆盖的每一格；两行表头合并为"上级 / 下级"；扫描件表格空白但有墨迹的单元格以 300dpi 单独复识 |
| 分块 | 以章节为单位，章节内按段落/句子/列表项/表格行装箱；标题、以冒号结尾的引导语、表名与后续内容绑定不拆开；过短的块只在同一父章节内合并，不跨顶层章节 |
| 长表格 | 按行拆块，每块重复表头和表名（标"续"），可设"每块最多 N 行"；可选"键值行"格式（`- 列名：值；…`），宽表检索效果更好 |
| 块上下文 | 每块首行 `> 章节：A > B > C ｜ 页码：3-4`（可切换为重复上级 `#` 标题，或不加；页码可关）；拆开的段落/表格按实际所在页标注 |
| 网页操作 | 拖拽上传、进度显示、Markdown 编辑、渲染预览、分块卡片（字数、超长/偏短标记、点击页码跳到原 PDF）、自定义分隔符、下载 |

输出示例：

```markdown
> 章节：信息安全管理制度 > 第二章 资产管理 > 2.1 资产清单 ｜ 页码：2-3

（续表）

| 序号 | 设备编号 | 类型 | 数量 | 存放位置 |
| --- | --- | --- | --- | --- |
| 25 | 设备-025 | 服务器 | 125 | 机房2号 |
...

===CHUNK===
```

## 参数说明

| 参数 | 默认 | 说明 |
|---|---|---|
| OCR 识别 | 自动 | 自动：仅对无文字层/乱码页识别；强制：所有含图像的页都重新识别；关闭 |
| OCR 清晰度 | 200 dpi | 150 更快但表格短数字易错；300 更准更慢 |
| 分隔符 | `===CHUNK===` | 仅改分隔符时直接在编辑器内替换，保留手工修改 |
| 最大 / 最小字数 | 1000 / 200 | 块字数含章节路径行；单行内容无法再拆时会提示超长 |
| 块上下文 | 章节路径 | 章节路径（面包屑）/ 重复上级标题 / 不添加 |
| 表格格式 | Markdown | Markdown 表格 / 键值行 |
| 表格每块最多行 | 0 | 0 表示只按字数拆分 |

修改分隔符以外的分块参数后点"应用分块设置"会在服务端重新分块（无需重新解析 PDF），会覆盖编辑器中的手工修改。

## 部署配置（环境变量）

| 变量 | 默认 | 说明 |
|---|---|---|
| `HOST` / `PORT` | `0.0.0.0` / `8000` | 监听地址 |
| `PDF2MD_WORKERS` | CPU 核数/2（1~3） | 解析进程数，每个约占 350MB 内存 |
| `PDF2MD_OCR_THREADS` | CPU 核数/进程数 | 每个进程 OCR 线程数 |
| `PDF2MD_MAX_MB` | 200 | 上传大小上限 |
| `PDF2MD_MAX_PAGES` | 2000 | 页数上限 |
| `PDF2MD_JOB_TTL` | 10800 | 任务结果与上传文件保留秒数 |
| `PDF2MD_WORK_DIR` | 临时目录 | 上传文件存放目录 |

本服务无登录鉴权，建议仅在内网使用或置于带鉴权的反向代理之后。

## 性能参考（4 核 CPU、无 GPU）

- 文本型：约 0.3–1 秒/页（19 页英文规范 9 秒）。
- 扫描型：约 5 秒/页（200 dpi，2 进程）。

## 目录结构

```
app/
  extract.py    工作进程：版面分析、OCR、表格框线识别 → 页面结构
  structure.py  页眉页脚清理、标题分级、段落/列表重建、跨页合并
  tables.py     表格清洗、跨页合并、Markdown/键值渲染
  chunker.py    章节分块、上下文、分隔符拼接
  pipeline.py   转换流水线（分批并行）
  server.py     FastAPI 服务与任务管理
web/            前端源码（React + Tailwind + shadcn，组件来自 cult-ui）
static/         前端构建产物（已提交，运行时无需 Node）
tests/
  make_samples.py  生成测试 PDF（文本型/复杂表格/双栏/扫描型）
  run_sample.py    命令行转换：python tests/run_sample.py a.pdf max_chars=800 table_mode=kv
  test_pipeline.py / test_api.py  自动化测试
  ui_smoke.py      浏览器冒烟测试（需另装 playwright）
```

运行测试：`.venv/bin/python -m pytest tests -q`（扫描件用例较慢，可加 `-m "not slow"`）。

## 前端开发

前端位于 `web/`，组件通过 shadcn CLI 从 [cult-ui](https://www.cult-ui.com/docs) 注册表引入（`components.json` 中的 `@cult-ui`），源码在 `web/src/components/ui/`，可直接修改。

```bash
cd web
pnpm install
pnpm dev            # 开发服务器，/api 代理到 http://localhost:8765（可用 PDF2MD_API 指定）
pnpm build          # 构建到 ../static，修改前端后需重新构建并提交
pnpm dlx shadcn@latest add @cult-ui/<组件名>   # 引入新的 cult-ui 组件
```

## 已知局限

- 扫描件中的无框线表格、复杂嵌套表格只能尽力而为；OCR 结果建议重点核对数字与专有名词（工具会提示 OCR 页数）。
- 图片仅在包含成段文字时保留文字；公式保留文字层，不转 LaTeX。
- "语义分块"基于章节结构与段落/句子边界，不调用大模型。
